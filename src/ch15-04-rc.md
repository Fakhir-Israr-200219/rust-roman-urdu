## `Rc<T>`, Reference-Counted Smart Pointer

Zyada tar cases mein ownership clear hoti hai: Aap exactly jaante hain ke
konsi variable kisi given value ko own karti hai. Lekin kuch cases mein ek hi
value ke multiple owners ho sakte hain. Misal ke taur par, graph data
structures mein multiple edges same node ki taraf point kar sakti hain, aur
woh node conceptually un tamam edges ke paas owned hota hai jo uski taraf
point karti hain. Kisi node ko tab tak clean up nahi karna chahiye jab tak uski
taraf point karne wali koi edge na ho aur is tarah uska koi owner na ho.

Aapko multiple ownership ko explicitly enable karna hota hai Rust type
`Rc<T>` ko use karke, jo *reference counting* ka abbreviation hai.
`Rc<T>` type kisi value ke references ki tadaad ko track karta hai taake yeh
determine kiya ja sake ke value abhi use mein hai ya nahi. Agar kisi value ke
zero references hon, to value ko bina kisi reference ke invalid hue clean up
kiya ja sakta hai.

`Rc<T>` ko family room mein rakhe ek TV ki tarah imagine karein. Jab ek person
TV dekhne ke liye andar aata hai, woh TV on karta hai. Doosre log room mein
aa kar TV dekh sakte hain. Jab last person room se bahar jata hai, woh TV off
kar deta hai kyun ke ab woh use nahi ho raha. Agar koi person TV ko us waqt off
kar de jab doosre log abhi bhi use dekh rahe hon, to baqi TV watchers mein
hungama mach jayega!

Hum `Rc<T>` type tab use karte hain jab hum apne program ke multiple parts ke
liye heap par kuch data allocate karna chahte hain taake woh us data ko read
kar saken, aur hum compile time par yeh determine nahi kar sakte ke data ko
sabse aakhir mein konsa part use karna khatam karega. Agar humein pata hota ke
sabse aakhir mein konsa part finish karega, to hum simply us part ko data ka
owner bana sakte the, aur compile time par enforce hone wale normal ownership
rules apply ho jate.

Note karein ke `Rc<T>` sirf single-threaded scenarios mein use karne ke liye
hai. Jab hum Chapter 16 mein concurrency discuss karenge, to hum
multithreaded programs mein reference counting karne ke tareeqe ko cover
karenge.

Hum `Rc::clone(&a)` ki jagah `a.clone()` call kar sakte the, lekin Rust ka

reference count ko increment karti hai, jo zyada time nahi leti. Data ki deep
copies mein kaafi waqt lag sakta hai. Reference counting ke liye `Rc::clone`
use karke, hum visually deep-copy wali clones aur un clones ke darmiyan farq
kar sakte hain jo reference count ko increase karti hain. Code mein performance
problems dhoondte waqt, humein sirf deep-copy clones ko consider karna hota hai
aur `Rc::clone` ki calls ko ignore kar sakte hain.

Hum dekh sakte hain ke `a` mein maujood `Rc<List>` ka initial reference count
1 hai; phir, har baar jab hum `clone` call karte hain, count 1 se barh jata hai.
Jab `c` scope se bahar jati hai, count 1 se kam ho jata hai. Reference count
ko decrease karne ke liye humein koi function call nahi karna padta, jis tarah
reference count increase karne ke liye humein `Rc::clone` call karna padta hai:
`Drop` trait ki implementation automatically reference count ko decrease kar deti
hai jab `Rc<T>` value scope se bahar jati hai.

Is example mein hum yeh nahi dekh sakte ke `main` ke end par jab pehle `b` aur
phir `a` scope se bahar jate hain, to count 0 ho jata hai aur `Rc<List>` poori
tarah clean up ho jati hai. `Rc<T>` use karne se ek single value ke multiple
owners ho sakte hain, aur count yeh ensure karta hai ke value tab tak valid
rahe jab tak owners mein se koi bhi abhi exist karta ho.

Immutable references ke zariye, `Rc<T>` aapko apne program ke multiple parts
ke darmiyan data ko sirf reading ke liye share karne deta hai. Agar `Rc<T>` aapko
multiple mutable references rakhne ki ijazat deta, to aap Chapter 4 mein
discuss kiye gaye borrowing rules mein se ek ko violate kar sakte the: Ek hi
place par multiple mutable borrows data races aur inconsistencies ka sabab ban
sakte hain. Lekin data ko mutate kar pana bohat useful hai! Agle section mein,
hum interior mutability pattern aur `RefCell<T>` type discuss karenge jise aap
`Rc<T>` ke saath use karke is immutability restriction ke saath kaam kar sakte
hain.
